## Form Answers (shared by both submissions)

### Q: What's ArmorClaude and ArmorCodex?

Intent-based security hooks for Claude Code and OpenAI Codex. Every tool
call / Bash command is checked against a declared intent plan plus policy
rules before execution. ArmorCodex = Codex CLI harness (PreToolUse /
PermissionRequest / PostToolUse hooks); fully local enforcement without an
ArmorIQ backend, optional signed intent tokens + audit logs when connected.

### Q: How to add policies in ArmorClaude/ArmorCodex?

From chat, plain text (no slash): `armor policy list`, `armor policy add
deny bash`, `armor policy template lockdown|strict-read-only|balanced`,
`armor policy default deny`. Changes are STAGED with a diff + risk warnings;
nothing applies until a human types `armor yes` in the terminal — the agent
itself cannot apply policy. Natural-language form also works
(`Policy new: deny Bash for payment data`).

### Q: Show the intent plan generated by ArmorClaude/ArmorCodex.

Demo plan for "run echo planned-ok":
```json
{"goal":"Run a single planned bash echo","steps":[
  {"tool":"Bash","reason":"echo planned-ok","metadata":{"inputs":{"command":"echo planned-ok"}}}]}
```
→ "Intent registered: 1 step(s). Plan stored locally."

Off-plan `whoami` then returns:
```json
{"permissionDecision":"deny","permissionDecisionReason":"ArmorCodex intent mismatch: parameters not allowed for Bash"}
```
— command never executed.

### Q: How are you finding this helpful?

It's a real fail-closed guardrail, not a lint: denial happens in the hook
layer before execution, malformed payloads deny too, and the human-only
`armor yes` gate closes the prompt-injection loop where an agent edits its own
rules. Enforce/monitor flip lets teams roll out gradually. Honest caveat:
Bash-only today (Codex hooks don't cover MCP/file edits) — their docs are
upfront about it. Setup worked headless with
ARMORIQ_API_KEY=*** ARMORCODEX_AUDIT_ENABLED=false
installer bypass; needs Codex CLI >=0.125 (0.80 silently skips hooks).
